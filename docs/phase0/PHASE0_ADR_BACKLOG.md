## E. Spike schedule and gates (authorised by FD-13; all NOT RUN as of 2026-10-09)

Spikes are **bounded evidence tasks, not product implementations**: code lives under `tests/spikes/` (or a throwaway branch), is deleted or rewritten under phase rules, and each outcome is recorded in its ADR. **A failed spike triggers the documented fallback; it is never forced green.** No extra macro phase is created — spikes run inside Phase 1 (early entry) and before the Phase 3 freezes.
