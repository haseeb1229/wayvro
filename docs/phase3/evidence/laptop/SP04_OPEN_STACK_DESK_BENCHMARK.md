> **LOCAL_SYNTHETIC_BENCHMARK — DESK/OPEN-DATA, NOT FIELD.** The cases were derived from the same OpenStreetMap
> extract the open stack was built from, so every S3 "accuracy" number below is **circular** (it tests plumbing,

Findings:
- **F1** Nominatim `/search` is not usable as autocomplete for Lahore riders: Roman-Urdu misspellings almost never
  match (5 %), 43 % of prefix/full requests return nothing. Expected (no fuzzy matching); Photon was meant to cover
  this and is NOT RUN.
- **F2** Even with circular truth, forward top-1 within 50 m is only 38 %: for polygons and roads the desk point
  (vertex mean / line midpoint) differs from Nominatim's centroid, and ambiguous road names (C08) never hit. A 50 m
  rule against polygon centroids is a desk artefact; the field truth is the pickup gate (SP-04 §4).
- **F3** The first desk list (v1) picked an OSM feature named "Shahi Qila" east of the border inside the bbox; the
  Nominatim reverse adapter refused the answer (`country_code` ≠ pk ⇒ MALFORMED_RESPONSE, breaker-countable, never a
  fabricated Pakistani address). Spec corrected to "Lahore Fort", list re-issued as v2, run repeated.
- **F4** OSRM routes the airport legs over `access=private` service roads next to the airport end point (the desk
  point is the airport polygon's vertex mean, i.e. airside). OSRM's car profile permits restricted access at the start
  or end of a route; whether real terminal pickups avoid this needs the C11 field cases.

## 7. Limitations

- Circular truth (OSM points vs an OSM-built stack); desk aliases written by Claude, not riders; no GPS fixes, drives,
  odometer, traffic, photos, blind ratings or founder review — every field metric is PENDING or N/A.
- Photon and Valhalla not run (bandwidth); the S3 autocomplete candidate is therefore untested. Nominatim search is a
  comparison only.
- Laptop under heavy unrelated load; latency indicative. Lahore clip only (not Pakistan-wide).
- The desk route review is an automated rule set plus an OSM one-way/access check; turn restrictions, U-turns,
  medians, closures and flyover/underpass level errors were not checked.
- The API geo gateway (cache, breaker, stale serving, budgets) was not in the loop.

## 8. What FA-05 field data and FA-06 accounts would still add

- **FA-05:** real pickup points (gates, forecourts) with GPS accuracy, rider-typed queries incl. real Roman-Urdu and
  Urdu, GPX/odometer/drive minutes for distance and ETA error, peak/off-peak, founder blind ratings and the §7.1 route
  review against observed signage — the only inputs that can gate or freeze.
- **FA-06:** S1 (Google) and S2 (Mapbox) components for the bundle comparison, with the free-allowance hard stop;
  S3 additionally needs Photon (and Valhalla) built from a verified jar/image.
