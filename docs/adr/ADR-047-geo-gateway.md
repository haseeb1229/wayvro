## Context
Phase 3 needs place search, reverse geocoding and routing for quotes (E06/E07) without putting provider keys on devices, without unbounded spend (I11, FD-14 envelope) and without leaking search text or locations (Q36). No geo port, no data cache in Valkey and no metrics SDK existed (F-P3-05). Provider terms couple geo content to map renderers (CON-P3-16).

## Decision
1. **Server-only provider calls through one gateway** (`apps/api/src/geo/`). Order for every call: normalise (NFKC, whitespace, Latin case-fold, Urdu kept, ACTIVE landmark alias expansion; points range-checked, inside the Pakistan envelope and rounded — reverse 4 dp, bias cell 2 dp — before anything else) → authz (consumer session + restriction guard, runtime switch per SKU, city ENABLED, SKU bound) → per-account rate limit → Valkey cache → budget → quota cool-down → circuit breaker → adapter with a TOTAL-time timeout inside the request deadline → validation/normalisation (Lahore formatter, sealed placeRefs) → cache write → usage meter.
2. **Cache**: keys `<prefix><providerKey>:<sku>:v1:<HMAC-SHA-256>` with the dedicated key class `geo_cache` (a dump or `MONITOR` reveals no text or location; provider-namespaced, so a provider switch never serves the previous provider's content). Effective TTL = min(adapter terms TTL, configured maximum); TTL 0 is never written; entries are validated on read (invalid ⇒ deleted, miss, `GEO_CACHE_ENTRY_INVALID`); a licence that forbids cross-user sharing puts the account into the key (routes: no cache). Stale serving (≤ 2 × TTL, `STALE_SERVED`) only for autocomplete and reverse geocoding; never for routes.
3. **placeRef**: `pr1.` + base64url(token id ‖ field-crypto envelope v1) under the new key class `place_refs`; plaintext `{v, pk, sku, pid, acct, city, exp}` (`city` added to the §7 sketch because the resolve route has no city parameter). Forged, foreign-account (no oracle), expired and other-provider tokens ⇒ 400 with `PLACE_REF_INVALID` / `PLACE_REF_EXPIRED` / `PLACE_REF_STALE`, no provider call. Forward-geocode suggestions are held per suggestion in Valkey (≤ placeRef lifetime and ≤ the terms TTL) so their placeRef resolves without a second provider call; when the terms TTL is 0 the GEOCODE mode is refused (an ADR-006 item: such a provider must expose place ids).
4. **Budgets** (`geo.provider_budgets`, maker-checker; DECREASE may be approved by its drafter with step-up — the database proves the decrease at draft time, the service re-checks it at activation): Valkey day/month call counters and a month micro-USD cost counter per (provider, SKU), consumed atomically before every provider attempt; UTC calendar windows on server time; signals at the row's thresholds (default 50/80/100 %) once per window (SET NX); exhausted ⇒ 503 `GEO_BUDGET_EXHAUSTED`. Local/test without an ACTIVE row ⇒ `GEO_LOCAL_DAILY_CALLS_PER_SKU`; staging/production without a row ⇒ SKU refused (`GEO_BUDGET_MISSING`).
5. **Circuit breaker** in `packages/server-runtime` (no dependency): per (provider, SKU) and process; opens at ≥ 50 % failures over ≥ 20 calls in a 60 s window or 5 consecutive timeouts; 30 s open; ≤ 3 half-open probes; Valkey hint `…breaker:<pk>:<sku>` (hint only). Quota answers (429-equivalent) and rejection of our own validated input are NEUTRAL for the breaker; quota opens a per-SKU cool-down instead (FG-05).
6. **Deadlines/retries**: geo reads = SKU timeout + `GEO_RETRY_SLACK_MS`; at most one retry, on a connect error only, while the remaining deadline still covers a full SKU timeout. Routing (`GeoRouting.route(request, deadline)`, consumed by pricing): one attempt, timeout = min(`GEO_ROUTE_TIMEOUT_MS`, time left), rounded 4-dp points and a 15-minute departure bucket; any refusal throws `RoutingUnavailableError` — never an estimated distance or ETA.
7. **Fail closed**: Valkey (limiter/budget store) unavailable ⇒ geo 503 with zero provider calls (OTP precedent); a cache read error alone is a miss only because the budget step that follows needs Valkey too.
8. **Licence-coherent binding**: `assertGeoBundle(GEO_RENDERER_KIND, registry)` refuses boot (`ProviderBindingError`, `GEO_LICENCE_BINDING_REFUSED`) when any bound adapter requires another renderer — including Google/Mapbox content with the text-first `none` renderer (ARCH-03) — or declares a malformed licence (TTL/price, provider key, SKU set).
9. **Privacy/observability**: route-template access logs; redaction of `polyline`, `place_ref`, `search_text/query`, `pickup`, `dropoff`, `bbox`, `route_geometry` keys and `pr1.` values; router-level errors never echo the path (Fastify `frameworkErrors`; `maxParamLength` 600 for placeRefs); the OTel exporter is wrapped to drop `url.full`/`url.query`/`http.url`/`http.target` for `/v1/geo/*` and CLIENT spans (no HTTP auto-instrumentation is registered today); gateway spans carry only provider key, SKU, cache status, outcome and latency. Hourly usage counters (no identity, text or coordinate) are rolled up every 15 min by the worker (`geo.usage-rollup`, idempotent, never lowers a recorded hour, `GEO_USAGE_GAP`) and kept 400 days.

## Evidence (2026-10-13, local Windows run, real PostgreSQL + PostGIS + Valkey, synthetic MOCK doubles)
Proven by tests: pipeline order and refusals (401 without session, 400 validation reasons, 404 switch, 429, 503); FG-01…FG-10; CS-01…CS-07; BUD-01…BUD-05, BUD-07, BUD-08 (BUD-03: 100 concurrent calls at budget − 1 ⇒ exactly one provider call); BUD-06 in the worker; BRK-01…BRK-05 + PROP-BREAKER (500 runs); PROP-POLYLINE, PROP-NORM; UNIT-FMT; UNIT-PLACEREF; LOG-GEO canary (logs, error bodies, audit rows, jobs, usage rows, Valkey keys); CONFIG-BUNDLE; BOOT-NEG (MOCK geo doubles refused in staging/production); migration 0011 (clean/prefix/re-run, CHECKs, guards, grants). Exact counts are in the P3.2 implementation report.

**Not proven here (NOT RUN / EXTERNAL):** any real provider adapter, terms or price (ADR-006, SP-04, P3.7); production key custody for `place_refs`/`geo_cache` (EG-05, like every key class); reverse-proxy/CDN access-log query-string scrubbing (deployment runbook, EXTERNAL until hosting exists); load/soak; the release-control switch store and catalog service-area lookup (P3.4/P3.1 — wired by the lead at merge; tests use seams).

## Consequences
- Geo availability depends on budgets and the breaker by design; every refusal has a client degrade path (type the address, drop a pin, "prices temporarily unavailable").
- Valkey becomes a (non-authoritative) data cache; a flush only produces misses.
- Two new key classes join the EG-05 KMS scope.

## Alternatives considered
Client-side provider SDKs (keys on device, no quotas, privacy) — rejected. A third-party API gateway product — rejected (another operated service). `opossum` for the breaker — rejected (in-house ~200 lines, property-tested, no dependency). Plain (unkeyed) cache keys — rejected (Valkey dumps would reveal searches and locations).

## Reversal path
Stages are independent and config-driven (TTL maxima, timeouts, breaker parameters, limits, budgets). A metrics stack (I07, Phase 4) can replace log signals without changing the gateway contract. The placeRef format is versioned (`pr1.`).
