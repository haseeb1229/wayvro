## Failure classification sources (fix 2026-10-17)

- **Google error reasons.** `google.api.ErrorReason` enum (domain `googleapis.com`) in googleapis
  `google/api/error_reason.proto` (https://raw.githubusercontent.com/googleapis/googleapis/master/google/api/error_reason.proto,
  read 2026-10-17). The file gives `ErrorInfo` examples (`reason`, `domain`, `metadata`) but no HTTP status per reason.
  Places API (New) and Routes API errors follow the Google API error model `{error:{code,message,status,details[]}}`;
  only `details[]` entries of `@type` `type.googleapis.com/google.rpc.ErrorInfo` with `domain` `googleapis.com` are
  read, and only their `reason`: credential/configuration reasons (`API_KEY_INVALID`, `API_KEY_*_BLOCKED`,
  `SERVICE_DISABLED`, `BILLING_DISABLED`, `CONSUMER_INVALID`, `CONSUMER_SUSPENDED`, `CREDENTIALS_MISSING`,
  `ACCOUNT_STATE_INVALID`, `GCP_SUSPENDED`) ⇒ `AUTH`; `RATE_LIMIT_EXCEEDED` / `RESOURCE_QUOTA_EXCEEDED` ⇒ `QUOTA`;
  anything else ⇒ the HTTP status decides. Which status and reason a real invalid/restricted/disabled key produces is
  EXTERNAL_ACCOUNT_REQUIRED (FA-06). Geocoding v3 keeps its documented HTTP-200 `status` mapping (no error model).
- **Retry-After.** RFC 9110 §10.2.3 (`Retry-After = HTTP-date / delay-seconds`) and §5.6.7 (IMF-fixdate, obsolete
  RFC 850 and asctime forms, which recipients must accept). Whether Google or Mapbox send `Retry-After` on 429 is
  EXTERNAL_ACCOUNT_REQUIRED; Mapbox's `X-Rate-Limit-*` headers are not read.
